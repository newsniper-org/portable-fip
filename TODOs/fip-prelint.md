# TODO: `fip-prelint`, a MIR-level checker, and crate-level MIR export

**Status:** IMPLEMENTED 2026-11-01 (`tools/fip-prelint`, `just prelint`); see
"Implementation" at the end for what was built, measured results and open items.
Decision record: `docs/decisions/2026-11-01-fip-prelint.md`.

## Why a rustc driver, not another syntactic pass

The remaining limits of `#[fip]`, strict mode and `fip_testkit::{callgraph,summaries}`
all come from seeing tokens only: no types, no name resolution. Examples are implicit
calls (`Drop`, operators, `Deref`, `Index`), panics from indexing and overflow,
method calls matched by name, `use` aliases, functions generated by macros, and
generic instantiations under `cargo check`. A pass that runs before type checking
inherits all of them. `fip-prelint` would therefore be a rustc driver reading MIR,
the stage clippy runs at, while running first in CI. It would be a host-only `std`
tool (`cargo fip-prelint`). `rustc_private` is not a crates.io dependency, so it
keeps the zero-external-dependency rule.

Toolchain on this host (checked): `rustc-dev` is installed for 1.99.1 (the Verus
toolchain) and 1.97.1, and `rustc_public` exists in 1.99.1.

## Crate-level opt-in: `#![cfg_attr(fip_prelint, fip::export)]`

Proposal (user, 2026-11-01): a crate that declares an export attribute has the MIR
of **all** its functions available to the driver, not only generic or `#[inline]`
ones.

### Probes (`/tmp/expmir`, `/tmp/mirprobe`, rustc 1.99.1)

**Attribute spelling.**

| case | result |
|---|---|
| `#![cfg_attr(fip_prelint, fip::export)]`, plain stable rustc (cfg off) | compiles; the attribute disappears |
| same, with `--cfg fip_prelint` and `-Zcrate-attr=feature(register_tool)`, `-Zcrate-attr=feature(custom_inner_attributes)`, `-Zcrate-attr=register_tool(fip)` (what the driver injects) | compiles |
| same with `--cfg fip_prelint` but no `register_tool` | error `cannot find module or crate fip` |
| typo `fip::exprot` under a registered tool | **accepted silently**: the driver must validate names under `fip::` itself |

A bare `#![export_fip]` is an unknown attribute on stable rustc, so plain builds
(e.g. Y4's) would break. Hence the `cfg_attr` form.

**End-to-end MIR lookup from a downstream driver.** A dependency `dep` with three
non-generic, non-`#[inline]` functions: `leaf` (`x + 1`), `looped` (a short
`while` loop) and `big` (80 statements, beyond the cross-crate inlining heuristic).
`dep` was built with and without `-Zalways-encode-mir`. A consumer crate was then
compiled by a probe driver (`rustc_driver::Callbacks::after_analysis`), which finds
each function's `DefId` through `module_children` of the dependency and calls
`tcx.is_mir_available(def_id)` and `tcx.optimized_mir(def_id)`.

| `dep` built | opt-level | `leaf` | `looped` | `big` |
|---|---|---|---|---|
| without flag | 0 | not available | not available | not available |
| with flag | 0 | available (2 blocks) | available (7 blocks) | available (241 blocks) |
| without flag | 2, 3 | **available** (1 block) | **available** (4 blocks) | not available |
| with flag | 2, 3 | available | available | available (161 blocks) |

Control: a `dep` built with the flag by 1.99.1 and read by rustc 1.97.1 fails with
`E0514 found crate dep compiled by an incompatible version of rustc`.

### What this means for the design

1. `-Zalways-encode-mir` makes every function's MIR readable downstream, checked
   end to end. The control without the flag fails at every opt-level for a
   function too large to inline.
2. At opt-level ≥ 2, rustc encodes MIR for small functions **anyway**
   (cross-crate inlinability). So "MIR is available" must not be read as "the crate
   opted in". The driver uses MIR from a dependency only if that dependency declares
   `fip::export`. Everything else stays ⊤, as today.
3. The flag is a session option, decided before parsing, while the attribute is only
   seen after parsing. The driver therefore sets the flag for every crate it
   compiles. The attribute is the contract ("use my MIR for verdicts"), not the
   switch. The metadata growth was small in the probe (2,073 → 2,870 bytes for a
   one-function crate).
4. Optimized MIR depends on opt-level: at 2/3 the MIR inliner has already run
   (`big`: 241 → 161 blocks). Calls into allocation functions remain visible after
   inlining, but the verdict should come from one fixed opt-level. Proposed:
   analyse MIR from a dedicated driver build at opt-level 0.
5. Encoded MIR is readable only by the same rustc. All crates of one analysis must
   be built by the pinned toolchain. Verdicts can cross toolchains (Y4 on 1.95,
   here 1.99) only through an exported **summary sidecar** (per-function allocation
   bound, recursion, frees, panics). Each sidecar is stamped with the crate hash, the
   driver version and the rustc version. It is a claim, so it is used only when the
   MIR is not readable.

### Not yet probed

- The same lookup through `rustc_public` (more stable API) instead of
  `rustc_middle`.
- `-Zbuild-std` with the driver, to analyse `core` instead of auditing the
  `CORE_TABLE` by hand (intrinsics would still need a table).
- Policy for crates.io dependencies: they cannot declare `fip::export`, so they
  stay ⊤ unless an explicit allow-list is added.
- Function pointers and `dyn` calls from outside the analysed crates remain ⊤.

**Mark syntax** (every key emitted, in this order):
`fip::mark(kind = "fip"|"fbip", n = N, strict = true|false, panic_macros = true|false[, param(g = K, ..)])`.
`fip-macros` emits `#[cfg_attr(fip_prelint, fip::mark(..))]` **only when the
expanding compiler is the driver**: the driver sets `FIP_PRELINT_DRIVER=1` in its own
process before expansion, and proc macros run in that process. Measured: emitting it
unconditionally makes every downstream crate without `check-cfg = ["cfg(fip_prelint)"]`
warn `unexpected_cfgs`, so plain builds now get no extra token at all.

### Analysis, as implemented

- **Roots:** local functions with `fip::mark`, through `rustc_public`
  (`local_crate().fn_defs()`, `all_tool_attrs()`).
- **Graph:** nodes are `Instance`s. A root is analysed with its identity arguments in
  `TypingEnv::post_analysis(root)`; every call is resolved with
  `Instance::try_resolve` after substituting the caller's arguments, so generic
  callees and closure arguments are analysed as the instantiation that runs.
  (`rustc_public`'s `Instance::resolve` works only fully monomorphized, so this part
  uses `rustc_middle`.)
- **MIR used:** local, crates whose root has `fip::export` (with `-Zalways-encode-mir`),
  `core`/`alloc`/`std` where a body exists; everything else `⊤` with the reason.
  Diverging `core`/`alloc`/`std` functions (`-> !`, e.g. `handle_alloc_error`,
  `raw_vec::handle_error`) are panic paths.
- **Costs:** per body, maximum over control-flow paths (not the sum over call sites:
  `if c { boxed(x) } else { boxed(y) }` is 1); cleanup (unwind) blocks are skipped;
  a block in a CFG cycle multiplies by `∞`. Recursive components: every non-zero
  component is widened to `∞`.
- **Events:** allocation entry points (1), `Drop` terminators on types with drop
  glue and deallocation entry points (possible free), `Assert` terminators and panic
  entry points (panic path; asserts whose condition is a constant that cannot fail,
  e.g. the shift check of `x >> 1`, the UB checks for null/misaligned pointers, and,
  since 2026-11-01, asserts that the value analysis proves unable to fire are
  skipped), unresolvable calls (`⊤`).
- **Terms:** a call of a callable generic parameter (`Fn*`, `FipFn`) is `alloc(g)`
  (named after the value parameter); another trait method on a generic parameter is
  `alloc(<T as Trait>::m)`; dropping a value whose type mentions a generic parameter is
  `drop(T)`. `param(g = K)` instantiates `alloc(g)` with `K` and `drop(F)` (for `g: F`)
  with 0. Terms left are a warning ("only relative to its generic parameters"),
  never a pass.
- **Verdicts:** `fip` / `fip(N)`: bound ≤ N, no possible free, no recursion; `fbip`:
  bound 0; `⊤`: one error per distinct unresolved leaf; `strict`: panic paths are
  errors with `panic_macros = false`, notes otherwise. `FIP_PRELINT_WARN_ONLY=1`
  (`--warn-only`) reports errors as warnings tagged `[error]`.
- **Declared parameter bounds at call sites** (added 2026-11-01, section "Resolved"
  below): every call whose resolved callee carries `param(g = K)` is checked against
  the bound of one call of the argument passed for `g`; `⊤` or more than `K` is an
  error at the call site. Checked in every body a root's analysis explores in an
  analysed crate (with that root's instantiation) and in every other local function
  and closure (identity arguments).

### Allocator entry points on rustc 1.99.1 (measured with `FIP_PRELINT_DUMP=1`)

The `std`/`alloc` MIR shipped with the toolchain is optimized MIR (inlined), so
`alloc::alloc::alloc` does not appear on these paths; the `__rust_*` symbols do.

| source | path to the entry point |
|---|---|
| `Box::new(x)` | `Box::<T>::new` → `alloc::boxed::box_new_uninit` → `Global::alloc_impl_runtime` → `__rust_alloc` or `__rust_alloc_zeroed` (after the empty marker `__rust_no_alloc_shim_is_unstable_v2`) |
| `vec![a, b, c]` | `Box::<[T; N]>::new_uninit` → `box_new_uninit` → as above |
| `Vec::with_capacity(n)` | `RawVecInner::with_capacity_in` → `RawVecInner::try_allocate_in` → `<Global as Allocator>::allocate{,_zeroed}` → `alloc_impl_runtime` → `__rust_alloc*` |
| `String::from(&str)` | `<u8 as ConvertVec>::to_vec` → `RawVecInner::with_capacity_in` → as above |
| `format!(..)` | `alloc::fmt::format` → `str::to_owned` → as above, and `alloc::fmt::format::format_inner` (no MIR: `⊤`) |
| `Vec::push` | `finish_grow` → `__rust_realloc` (allocation + free) or `__rust_alloc*`; path maximum 1 |
| drop of a `Box` | drop glue → `<Box<T> as Drop>::drop` → `Global::deallocate` → `__rust_dealloc` |

`alloc::alloc::{alloc, alloc_zeroed, exchange_malloc, realloc, dealloc}` stay in the
tables for direct calls and other toolchains; `exchange_malloc` is not on any path above.

## Resolved 2026-11-01: declared parameter bounds at call sites

Measured first (`/tmp/item7`, `fip-strict` as an exported workspace member):

```rust
#[fip_macros::fip(strict = true, param(g = 0))]
pub fn f<F: FipFn<(u8,), Output = Box<u8>>>(g: F) -> u8 { *g.call((1,)) }

pub fn non_root_caller() -> u8 { f(fip_macros::fip_fn!(|x: u8| Box::new(x))) }

#[fip_macros::fip]
pub fn root_caller() -> u8 { f(fip_macros::fip_fn!(|x: u8| Box::new(x))) }

#[fip_macros::fip(1)]
pub fn root_caller_budget1() -> u8 { f(fip_macros::fip_fn!(|x: u8| Box::new(x))) }
```

| caller | before (`cargo fip-prelint`) | after (fixture `param_bounds`) |
|---|---|---|
| `non_root_caller` | nothing | error at the call: the argument `Certified<1, {closure}>` may allocate 1 time per call, `f` declares `param(g = 0)`; chain `<Certified<..> as FipFn<(u8,)>>::call` → closure → `Box::new` |
| `root_caller` (`#[fip]`) | may allocate 1, at most 0 (its own budget); may free | the same two errors, plus the argument error |
| `root_caller_budget1` (`#[fip(1)]`) | may free only | may free, plus the argument error |
| `f` | may free (`*g.call(..)` drops the `Box`), a real finding about the example | unchanged |

Plain `cargo check` accepts the file; a full build rejects it through the
post-monomorphisation assertion. The driver now rejects it under `cargo check`.

**Rule** (port of `fip_testkit::summaries`' `ArgumentExceedsDeclared`). At a call
whose resolved callee carries `fip::mark(.., param(g = K))`, `g`'s declared type is
a generic type parameter `F` (`g: F`, `&F`, `&mut F`); the argument is the actual `T`
for `F` at the call site. Its bound is that of one call: the callable methods of
`F`'s bounds in the callee's `param_env` (`FipFn::call`, `Fn::call`,
`FnMut::call_mut`, `FnOnce::call_once`, elaborated) are resolved for `T` and analysed
like any callee, maximum over them. So a closure is its body, a `fip_fn!` value
(`Certified<N, C>`) is `Certified::call` and the closure in it (the computed bound,
not the claimed `N`), a named function is its `Fn` shim and the function, a function
pointer is `⊤`. A `T` that is a generic parameter of the analysed function is the term
`alloc(h)`, instantiated by that function's own `param(h = K')`. Violation: `⊤`, or no
terms left and the bound above `K`; reported at the call site with the argument's
allocation chain. Terms left (a generic caller without `param`) are not reported:
that caller's instantiations are checked where they are analysed, as in the token
rule. A `g` whose type is not a generic parameter is `⊤` at every call; a generic
parameter without a callable bound bounds no call and is skipped.

**Which call sites.** (1) Every body a root's analysis explores in the local crate or
in a crate declaring `fip::export`, with the root's instantiation: this catches calls
in generic helpers instantiated with a concrete argument (`through_forward` →
`forward::<{closure}>` → `apply`), and the error counts against that root. (2) Every
other local function, method and closure with MIR (`mir_keys`), with identity
arguments; only the arguments' entry points are explored there, not the body's other
callees. A violation found from several roots or by both is reported once.

**Rendering.** Chains through sources outside the analysed workspace (absolute paths,
e.g. `fip-strict` used as a path dependency) now show the step without its
machine-dependent location instead of `path:line`; nothing in the existing expected
files had such a path.

**Self-check:** 16 call sites checked, 0 violations, `selfcheck.expected` unchanged
(see "Self-check" above).

## Resolved 2026-11-01: path-insensitive panics

Every `Assert` terminator (bounds, overflow, division, negation check) was a panic
path, also behind a guard, because MIR at opt-level 0 keeps the check after
`if i < xs.len()`. The driver now runs an intraprocedural value analysis on every
body with such an assert (`tools/fip-prelint/src/value.rs`) and drops the asserts it
proves unable to fire on all paths reaching them.

**Method.** Difference bounds `x - y ≤ c` (a zone, with type bounds) between integer
locals, slice lengths (`PtrMetadata` of a slice pointer, also through `&(*p)`
reborrows), results of checked operations, `start`/`end` of `Range<integer>` and
the payload of `Option<integer>`. Comparisons feeding a `SwitchInt` refine each
edge; infeasible edges are dropped; a successful check adds its condition; loops
are widened at their heads. A `for` loop over `a..b` is modelled from the contract
of `Range<integer>` (`into_iter` is the identity; `next` yields `start` and
increments it while `start < end`, and never changes `end`). Soundness: a local whose
address is taken (`&mut x`, `&raw x`, `&x` of a place with interior mutability) is
never tracked (a `Range` passed by `&mut` only to `next` excepted); calls only
forget their destination; anything else unknown forgets the assigned local;
128-bit arithmetic and signed division overflow are not decided; unsure means the
assert stays.

**Measured** (`cargo fip-prelint --warn-only` on the workspace, notes per crate;
errors and warnings unchanged):

## Fixed 2026-11-01: dependencies that declare `fip::export`

Non-member dependencies (git or path) were compiled without the driver, so their
`fip::export` was inactive and every call into them was ⊤. `cargo fip-prelint` now uses
