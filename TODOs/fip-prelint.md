# TODO: `fip-prelint`, a MIR-level checker, and crate-level MIR export

**Status:** IMPLEMENTED 2026-11-01 (`tools/fip-prelint`, `just prelint`); see
"Implementation" at the end for what was built, measured results and open items.
Decision record: `docs/decisions/2026-11-01-fip-prelint.md`.

## Why a rustc driver, not another syntactic pass

The remaining limits of `#[fip]`, strict mode and `fip_testkit::{callgraph,summaries}`
all come from seeing tokens only: no types, no name resolution. Examples are implicit
calls (`Drop`, operators, `Deref`, `Index`), panics from indexing and overflow,
method calls matched by name, `use` aliases, functions generated by macros, and
generic instantiations under `cargo check`. A pass that runs before type checking
inherits all of them. `fip-prelint` would therefore be a rustc driver reading MIR,
the stage clippy runs at, while running first in CI. It would be a host-only `std`
tool (`cargo fip-prelint`). `rustc_private` is not a crates.io dependency, so it
keeps the zero-external-dependency rule.

Toolchain on this host (checked): `rustc-dev` is installed for 1.99.1 (the Verus
toolchain) and 1.97.1, and `rustc_public` exists in 1.99.1.

## Crate-level opt-in: `#![cfg_attr(fip_prelint, fip::export)]`

Proposal (user, 2026-11-01): a crate that declares an export attribute has the MIR
of **all** its functions available to the driver, not only generic or `#[inline]`
ones.

### Probes (`/tmp/expmir`, `/tmp/mirprobe`, rustc 1.99.1)

**Attribute spelling.**

| case | result |
|---|---|
| `#![cfg_attr(fip_prelint, fip::export)]`, plain stable rustc (cfg off) | compiles; the attribute disappears |
| same, with `--cfg fip_prelint` and `-Zcrate-attr=feature(register_tool)`, `-Zcrate-attr=feature(custom_inner_attributes)`, `-Zcrate-attr=register_tool(fip)` (what the driver injects) | compiles |
| same with `--cfg fip_prelint` but no `register_tool` | error `cannot find module or crate fip` |
| typo `fip::exprot` under a registered tool | **accepted silently**: the driver must validate names under `fip::` itself |

A bare `#![export_fip]` is an unknown attribute on stable rustc, so plain builds
(e.g. Y4's) would break. Hence the `cfg_attr` form.

**End-to-end MIR lookup from a downstream driver.** A dependency `dep` with three
non-generic, non-`#[inline]` functions: `leaf` (`x + 1`), `looped` (a short
`while` loop) and `big` (80 statements, beyond the cross-crate inlining heuristic).
`dep` was built with and without `-Zalways-encode-mir`. A consumer crate was then
compiled by a probe driver (`rustc_driver::Callbacks::after_analysis`), which finds
each function's `DefId` through `module_children` of the dependency and calls
`tcx.is_mir_available(def_id)` and `tcx.optimized_mir(def_id)`.

| `dep` built | opt-level | `leaf` | `looped` | `big` |
|---|---|---|---|---|
| without flag | 0 | not available | not available | not available |
| with flag | 0 | available (2 blocks) | available (7 blocks) | available (241 blocks) |
| without flag | 2, 3 | **available** (1 block) | **available** (4 blocks) | not available |
| with flag | 2, 3 | available | available | available (161 blocks) |

Control: a `dep` built with the flag by 1.99.1 and read by rustc 1.97.1 fails with
`E0514 found crate dep compiled by an incompatible version of rustc`.

### What this means for the design

1. `-Zalways-encode-mir` makes every function's MIR readable downstream, checked
   end to end. The control without the flag fails at every opt-level for a
   function too large to inline.
2. At opt-level ≥ 2, rustc encodes MIR for small functions **anyway**
   (cross-crate inlinability). So "MIR is available" must not be read as "the crate
   opted in". The driver uses MIR from a dependency only if that dependency declares
   `fip::export`. Everything else stays ⊤, as today.
3. The flag is a session option, decided before parsing, while the attribute is only
   seen after parsing. The driver therefore sets the flag for every crate it
   compiles. The attribute is the contract ("use my MIR for verdicts"), not the
   switch. The metadata growth was small in the probe (2,073 → 2,870 bytes for a
   one-function crate).
4. Optimized MIR depends on opt-level: at 2/3 the MIR inliner has already run
   (`big`: 241 → 161 blocks). Calls into allocation functions remain visible after
   inlining, but the verdict should come from one fixed opt-level. Proposed:
   analyse MIR from a dedicated driver build at opt-level 0.
5. Encoded MIR is readable only by the same rustc. All crates of one analysis must
   be built by the pinned toolchain. Verdicts can cross toolchains (Y4 on 1.95,
   here 1.99) only through an exported **summary sidecar** (per-function allocation
   bound, recursion, frees, panics). Each sidecar is stamped with the crate hash, the
   driver version and the rustc version. It is a claim, so it is used only when the
   MIR is not readable.

### Not yet probed

- The same lookup through `rustc_public` (more stable API) instead of
  `rustc_middle`.
- `-Zbuild-std` with the driver, to analyse `core` instead of auditing the
  `CORE_TABLE` by hand (intrinsics would still need a table).
- Policy for crates.io dependencies: they cannot declare `fip::export`, so they
  stay ⊤ unless an explicit allow-list is added.
- Function pointers and `dyn` calls from outside the analysed crates remain ⊤.

**Mark syntax** (every key emitted, in this order):
`fip::mark(kind = "fip"|"fbip", n = N, strict = true|false, panic_macros = true|false[, param(g = K, ..)])`.
`fip-macros` emits `#[cfg_attr(fip_prelint, fip::mark(..))]` **only when the
expanding compiler is the driver**: the driver sets `FIP_PRELINT_DRIVER=1` in its own
process before expansion, and proc macros run in that process. Measured: emitting it
unconditionally makes every downstream crate without `check-cfg = ["cfg(fip_prelint)"]`
warn `unexpected_cfgs`, so plain builds now get no extra token at all.

### Analysis, as implemented

- **Roots:** local functions with `fip::mark`, through `rustc_public`
  (`local_crate().fn_defs()`, `all_tool_attrs()`).
- **Graph:** nodes are `Instance`s. A root is analysed with its identity arguments in
  `TypingEnv::post_analysis(root)`; every call is resolved with
  `Instance::try_resolve` after substituting the caller's arguments, so generic
  callees and closure arguments are analysed as the instantiation that runs.
  (`rustc_public`'s `Instance::resolve` works only fully monomorphized, so this part
  uses `rustc_middle`.)
- **MIR used:** local, crates whose root has `fip::export` (with `-Zalways-encode-mir`),
  `core`/`alloc`/`std` where a body exists; everything else `⊤` with the reason.
  Diverging `core`/`alloc`/`std` functions (`-> !`, e.g. `handle_alloc_error`,
  `raw_vec::handle_error`) are panic paths.
- **Costs:** per body, maximum over control-flow paths (not the sum over call sites:
  `if c { boxed(x) } else { boxed(y) }` is 1); cleanup (unwind) blocks are skipped;
  a block in a CFG cycle multiplies by `∞`. Recursive components: every non-zero
  component is widened to `∞`.
- **Events:** allocation entry points (1), `Drop` terminators on types with drop
  glue and deallocation entry points (possible free), `Assert` terminators and panic
  entry points (panic path; asserts whose condition is a constant that cannot fail,
  e.g. the shift check of `x >> 1`, the UB checks for null/misaligned pointers, and,
  since 2026-11-01, asserts that the value analysis proves unable to fire are
  skipped), unresolvable calls (`⊤`).
- **Terms:** a call of a callable generic parameter (`Fn*`, `FipFn`) is `alloc(g)`
  (named after the value parameter); another trait method on a generic parameter is
  `alloc(<T as Trait>::m)`; dropping a value whose type mentions a generic parameter is
  `drop(T)`. `param(g = K)` instantiates `alloc(g)` with `K` and `drop(F)` (for `g: F`)
  with 0. Terms left are a warning ("only relative to its generic parameters"),
  never a pass.
- **Verdicts:** `fip` / `fip(N)`: bound ≤ N, no possible free, no recursion; `fbip`:
  bound 0; `⊤`: one error per distinct unresolved leaf; `strict`: panic paths are
  errors with `panic_macros = false`, notes otherwise. `FIP_PRELINT_WARN_ONLY=1`
  (`--warn-only`) reports errors as warnings tagged `[error]`.
- **Declared parameter bounds at call sites** (added 2026-11-01, section "Resolved"
  below): every call whose resolved callee carries `param(g = K)` is checked against
  the bound of one call of the argument passed for `g`; `⊤` or more than `K` is an
  error at the call site. Checked in every body a root's analysis explores in an
  analysed crate (with that root's instantiation) and in every other local function
  and closure (identity arguments).

### Allocator entry points on rustc 1.99.1 (measured with `FIP_PRELINT_DUMP=1`)

The `std`/`alloc` MIR shipped with the toolchain is optimized MIR (inlined), so
`alloc::alloc::alloc` does not appear on these paths; the `__rust_*` symbols do.

| source | path to the entry point |
|---|---|
| `Box::new(x)` | `Box::<T>::new` → `alloc::boxed::box_new_uninit` → `Global::alloc_impl_runtime` → `__rust_alloc` or `__rust_alloc_zeroed` (after the empty marker `__rust_no_alloc_shim_is_unstable_v2`) |
| `vec![a, b, c]` | `Box::<[T; N]>::new_uninit` → `box_new_uninit` → as above |
| `Vec::with_capacity(n)` | `RawVecInner::with_capacity_in` → `RawVecInner::try_allocate_in` → `<Global as Allocator>::allocate{,_zeroed}` → `alloc_impl_runtime` → `__rust_alloc*` |
| `String::from(&str)` | `<u8 as ConvertVec>::to_vec` → `RawVecInner::with_capacity_in` → as above |
| `format!(..)` | `alloc::fmt::format` → `str::to_owned` → as above, and `alloc::fmt::format::format_inner` (no MIR: `⊤`) |
| `Vec::push` | `finish_grow` → `__rust_realloc` (allocation + free) or `__rust_alloc*`; path maximum 1 |
| drop of a `Box` | drop glue → `<Box<T> as Drop>::drop` → `Global::deallocate` → `__rust_dealloc` |

`alloc::alloc::{alloc, alloc_zeroed, exchange_malloc, realloc, dealloc}` stay in the
tables for direct calls and other toolchains; `exchange_malloc` is not on any path above.

post-monomorphisation assertion. The driver now rejects it under `cargo check`.

**Rule** (port of `fip_testkit::summaries`' `ArgumentExceedsDeclared`). At a call
whose resolved callee carries `fip::mark(.., param(g = K))`, `g`'s declared type is
a generic type parameter `F` (`g: F`, `&F`, `&mut F`); the argument is the actual `T`
for `F` at the call site. Its bound is that of one call: the callable methods of
`F`'s bounds in the callee's `param_env` (`FipFn::call`, `Fn::call`,
`FnMut::call_mut`, `FnOnce::call_once`, elaborated) are resolved for `T` and analysed
like any callee, maximum over them. So a closure is its body, a `fip_fn!` value
(`Certified<N, C>`) is `Certified::call` and the closure in it (the computed bound,
not the claimed `N`), a named function is its `Fn` shim and the function, a function
pointer is `⊤`. A `T` that is a generic parameter of the analysed function is the term
`alloc(h)`, instantiated by that function's own `param(h = K')`. Violation: `⊤`, or no
terms left and the bound above `K`; reported at the call site with the argument's
allocation chain. Terms left (a generic caller without `param`) are not reported:
that caller's instantiations are checked where they are analysed, as in the token
rule. A `g` whose type is not a generic parameter is `⊤` at every call; a generic
parameter without a callable bound bounds no call and is skipped.

**Which call sites.** (1) Every body a root's analysis explores in the local crate or
in a crate declaring `fip::export`, with the root's instantiation: this catches calls
in generic helpers instantiated with a concrete argument (`through_forward` →
`forward::<{closure}>` → `apply`), and the error counts against that root. (2) Every
other local function, method and closure with MIR (`mir_keys`), with identity
arguments; only the arguments' entry points are explored there, not the body's other
callees. A violation found from several roots or by both is reported once.

**Rendering.** Chains through sources outside the analysed workspace (absolute paths,
e.g. `fip-strict` used as a path dependency) now show the step without its
machine-dependent location instead of `path:line`; nothing in the existing expected
files had such a path.

**Self-check:** 16 call sites checked, 0 violations, `selfcheck.expected` unchanged
(see "Self-check" above).

## Resolved 2026-11-01: path-insensitive panics

Every `Assert` terminator (bounds, overflow, division, negation check) was a panic
path, also behind a guard, because MIR at opt-level 0 keeps the check after
`if i < xs.len()`. The driver now runs an intraprocedural value analysis on every
body with such an assert (`tools/fip-prelint/src/value.rs`) and drops the asserts it
proves unable to fire on all paths reaching them.

**Method.** Difference bounds `x - y ≤ c` (a zone, with type bounds) between integer
locals, slice lengths (`PtrMetadata` of a slice pointer, also through `&(*p)`
reborrows), results of checked operations, `start`/`end` of `Range<integer>` and
the payload of `Option<integer>`. Comparisons feeding a `SwitchInt` refine each
edge; infeasible edges are dropped; a successful check adds its condition; loops
are widened at their heads. A `for` loop over `a..b` is modelled from the contract
of `Range<integer>` (`into_iter` is the identity; `next` yields `start` and
increments it while `start < end`, and never changes `end`). Soundness: a local whose
address is taken (`&mut x`, `&raw x`, `&x` of a place with interior mutability) is
never tracked (a `Range` passed by `&mut` only to `next` excepted); calls only
forget their destination; anything else unknown forgets the assigned local;
128-bit arithmetic and signed division overflow are not decided; unsure means the
assert stays.

## Resolved 2026-11-02: iterator contracts (limits plan L3)

Plan: `docs/decisions/2026-11-02-fip-prelint-limits-plan.md`, L3 (item 6 of its order).
Only `Range<integer>` was modelled; M3's `rev()`, `0..=n`, `enumerate` and `zip`
loops were reported.

**`zip`'s panic, located first** (the plan's open question, with
`FIP_PRELINT_DUMP=1` and the new `FIP_PRELINT_DUMP_MIR=size_hint`): it is
`assert!(0 < pointee_size && pointee_size <= isize::MAX as usize)` in
`offset_from_unsigned`, inlined into `<slice::Iter<T> as Iterator>::size_hint`, which
`Iterator::zip` calls through `TrustedRandomAccess::size`. `pointee_size` is the
generic constant `<T as SizedTypeProperties>::SIZE`, which the value analysis did not
evaluate. Fix: constants are evaluated with the analysed instance's arguments
(`T = u8`: `0 < 1 <= isize::MAX`, the panic branch is infeasible). It is not a
reachable `std` panic for a sized `T`; for a generic `T` it stays reported.

**Contracts** (`value::Contract`; matched by lang item or by the iterator type's
defining path in `core`): `RangeInclusive<int>` (yields `start <= end`; `start`
forgotten after `next`), `Rev<Range<int>>` (`end -= 1`, yields the new `end` while
`start < end`), `slice::Iter{,Mut}` (position and length), `Enumerate` of a slice
iterator (yields the index, below the length) and `Zip` of two slice iterators (below
both lengths); constructors `RangeInclusive::new`, `Iterator::rev`, `<[T]>::iter{,_mut}`,
`IntoIterator` of a slice reference, `Iterator::enumerate`, `Iterator::zip`. The
`Enumerate` contract also covers `self.count += 1` in `Enumerate::next` (an overflow
check inherited from the caller, `#[rustc_inherit_overflow_checks]`): `count` is the
index of the item just produced, so it cannot overflow. A differential test runs
each real iterator on boundary inputs (`u8` up to 255, empty and short slices) and
checks every fact the contract assumes. It **found** that on rustc 1.99.1
`RangeInclusive`'s `start` wraps after the last item (`255..=255` ends with
`start == 0`), so the contract forgets `start` instead of the plan's "start grows";
the test pins the measured behaviour.

## Resolved 2026-11-02: function pointers, trait objects and trait method contracts (limits plan L4)

Plan: `docs/decisions/2026-11-02-fip-prelint-limits-plan.md`, L4 (item 7 of its order).
Every call through a function pointer and every `dyn` call was `⊤`, a `param(g = K)`
on a non-generic parameter was `⊤` at every call site, and a `fip::mark` on a trait
method declaration was analysed as a root without a body (`⊤`, "no MIR").

**(1) Origin in the body** (`analysis::origin_of`, a must-analysis): the value of a
function pointer or `&dyn` receiver is followed through copies, moves, reborrows `&*p`
and upcasts to the assignments that can produce it; if all of them reify the same
function item or closure (`ReifyFnPointer`, `ClosureFnPointer`), or unsize a pointer
to the same concrete type (`Unsize`), the call is that function, or that type's method
(resolved with `Self` replaced). A local borrowed mutably, written in a field, or the
destination of a call is not followed; a parameter is its own origin. Two origins, a
pointer loaded from memory, a call result: `⊤` as before. `Box<dyn ..>` receivers are
not followed (their dereference is elaborated into raw-pointer projections).

**(2) `param(g = K)` on function pointers and `&dyn Fn*`/`&dyn FipFn`.** Inside the
function, a call through `g` counts `K` allocations plus what the function's own mark
allows (`fbip`: a possible free and recursion; not strict: a panic path), so a `fip`
caller of an `fbip` function sees the frees its argument may do. At every analysed
call site the argument's origin in the caller must be known: a reified function or
closure, a closure or other value unsized to the trait object (its `call*` methods),
or a parameter of the caller declared `param(h = K')` (its declaration); anything else
is `⊤` at the call site. The argument must allocate at most `K` times per call and,
for a `fip` callee, must not free or recurse (for `strict = true, panic_macros =
false`: not panic), because the callee counts the call by its declaration only.

**(3) Contracts on trait methods.** `#[cfg_attr(fip_prelint, fip::mark(..))]` on a
trait method declaration (written by hand; also read from exported crates) is a
contract: a `dyn` call of the method costs the declared bound (`n`; for `fbip` also a
free and recursion; a panic path unless `strict = true, panic_macros = false`).
Every implementation is checked against it as a root in the crate that contains it
(the trait's default body for an impl that keeps it, in the impl's typing
environment); a dependency that declares `fip::export` (compiled by the driver without
roots) checks its own implementations too. An implementation in a crate without
`fip::export` is `⊤`, an error in every analysed crate whose crate graph contains it.
`param(..)` in a contract is rejected (its dynamic calls stay `⊤`). Without a
contract, `dyn` calls of unknown origin stay `⊤`. No closed-world candidate list.

## Resolved 2026-11-02: FFI foreign functions: certified XOR excluded XOR error

Every foreign function (`extern` block item) reachable from a FIP-checked function must be in exactly one of:
- (a) **certified**: `#[fip_cert(evidence = "..", allocs = N)]` (or `#[fip(..., evidence = "..")]`) under `#[fip_extern]` on the `extern` block. Requires non-empty `evidence = ".."`. ## Resolved 2026-11-02: `#[fip_impl]` compares panic strictness with the contract

## Resolved 2026-11-03: function pointers from constants, immutable statics and local aggregates (top plan T1.1–T1.3)

Plan: `docs/decisions/2026-11-03-fip-prelint-top-plan.md`, T1 candidates 1–3 (item 2
of its order). Before: `origin_of` gave up on `Operand::Constant`, on projections and
on loads, so `CONE(x)`, `ONE(x)`, `TABLE[i](x)`, `(SOPS.f)(x)` and `(o.f)(x)` with a
local `o = Ops { f: plus1 }` were `⊤`.

**Mechanism** (`src/analysis.rs`).

- `Origin::Const(c)`: an `Operand::Constant`. `Origin::Load(c, proj)`: a place
  `(*l).proj` where `l` holds the reference constant `c` (`_3 = const {alloc1:
  &[fn(u8) -> u8; 2]}`; `_2 = copy (*_3)[_4]`). An `Index` by a local assigned one
  integer constant becomes a `ConstantIndex` (`MIXED[2]`).
- `Analysis::data_targets`: evaluates `c` in the instance (`mir::Const::eval`). A
  function pointer constant is its `GlobalAlloc::Function` instance. For a load, the
  referenced allocation must be immutable: a `GlobalAlloc::Static` that is not `static
  mut`, not thread-local, not foreign, of a `Freeze` type (initializer from
  `eval_static_initializer`, also across crates), or `GlobalAlloc::Memory`; and its
  `mutability` must be `Not`. A `const` slice evaluates to `ConstValue::Indirect`: the
  wide pointer is read from that memory. The projections are walked over the layout
  (struct and tuple fields; array and slice elements, all of them for an unknown index,
  at most 256); every value read must be a pointer to a function. Anything else
  (a dereference inside the data, an enum variant, a non-function value): `None`, `⊤`.
- One candidate is the call; several are `Item::Alt`, a site costing the maximum of
  its alternatives with the events of every one (`site_cost`). Each candidate is
  checked at the call like a direct callee (declared parameter bounds,
  `fip::requires`).
- `OriginCx::field`: `l.f` (chains of fields) where `l` is a non-parameter local
  assigned only as whole struct or tuple aggregates, never mutably borrowed or written
  in part ([`Unstable`]), of a `Freeze` type; the origin of the field's operand, if
  every aggregate agrees.
- At call sites of a callee with `param(p = K)`, a constant or table argument gives its
  candidates as alternatives (label `one of ..`).

**Soundness.** A constant has one value. Memory of an immutable `Freeze` static or of
a constant is never written after initialisation (a write is undefined behaviour), so a
load yields one of the pointers in the initializer; an unknown index takes every
element. The local-aggregate rule is the existing must-origin over whole-local writes.

## Resolved 2026-11-03: private functions checked at their call sites (top plan T4.3)

Plan: `docs/decisions/2026-11-03-fip-prelint-top-plan.md`, T4 candidate 3 (item 5 of
its order); candidate 2 (context-sensitive resolution for roots) came with B.

**Before.** `mid(q) { apply_ptr(q, x) }` without `param(q = ..)` was reported `⊤` at
its call of `apply_ptr` whenever `mid` was checked on its own (every local function
is), even when every caller passes a known function. An allocating argument passed by
a non-root caller was covered only by that `⊤`.

**Mechanism.**

- `analysis::inferable_private`: local `fn`s and inherent methods that are not
  exported by name, not trait methods or trait implementations, without an external
  symbol, never named outside the callee position of a call (HIR scan of every body,
  closures, consts and statics included), with a callable-typed parameter. All their
  callers are analysed code of this crate.
- `ArgSite`/`ArgViolation` record the caller (`caller_def`) and whether the argument
  is an unbound, undeclared parameter of the caller (`from_param`, `unbound_param`).
- `report.rs`: for such a function checked on its own, violations with `from_param` in
  its own body are not reported.
- `Analysis::arguments_in(owner)`: every call of such a function explores its body
  bound to what the call passes (`call_binds`), so its call sites are checked per
  caller (an unknown argument explores it unbound and reports the `⊤`). An inferable
  owner passing its own unbound parameter on leaves that to its own call sites.
- `arguments_in` reads the owner's body with no current node (`bind_of` is `None`),
  and nodes created then have no parent (a stale-binding hazard found while
  implementing).

**Soundness.** Such a function can be called only by name from this crate's code (no
pointer to it exists, it is not callable through a trait, and it is not reachable by

## Resolved 2026-11-03: contracts with `param(..)` (top plan T5)

Plan: `docs/decisions/2026-11-03-fip-prelint-top-plan.md`, T5 (item 9 of its order),
with B.

**Before.** `param(g = K)` in a trait method contract was rejected by the driver
("its dynamic calls are `⊤`", `report.rs`) and by `fip-macros` on a declaration;
`Crates::contract_of` ignored such a contract, so a dynamic call of the method was `⊤`
and its implementations were not checked against it.

**Mechanism.**

- Driver: `Crates::contract_of` keeps contracts with `param(..)`. Where the contract is
  declared, each `g` must name a parameter of function-pointer or callable
  trait-object type (`fn(..)`, `&dyn Fn*`, `&mut dyn Fn*`, `Box<dyn Fn*>`,
  `&Box<dyn Fn*>`, `&dyn FipFn`; `analysis::contract_callable`), else an error. A
  generic `G: Fn*` makes the method not dyn-compatible; its calls resolve per
  instance and need no contract parameter.
- Implementations inherit the contract's bounds, mapped by position to their own
  parameter names (`analysis::inherited_params`): `check_implementation` runs the
  body with the renamed contract (`g` costs `K` with the contract's permissions), and
  `Crates::param_mark` returns the renamed contract for an implementation whose own
  mark declares no `param(..)`, so its static call sites are checked and its body
  counts a declared parameter as usual. An implementation that is itself a root and
  declares no `param(..)` takes the contract's.
- Calls through the contract: `note_arg_site` accepts a `Virtual` callee (a `dyn`
  call) and the trait method itself (a call on a type parameter that does not
  resolve, `node_contract`; also from `arguments_in` for bodies that are not roots),
  and checks the argument for `g` against `K` and the contract's permissions, like an
  ordinary call site.
- An implementation's own `param(g = K')` with `K' < K` is "weaker than the contract"
  (dynamic callers may pass what it does not accept): an error at the implementation.
- `fip-macros`: `param(..)` without `strict = true` is accepted on a trait method
  declaration when the name is a parameter whose type tokens are a function pointer
  or a callable trait object (the same list); on a function with a body it still
  "requires `strict = true` before it". `strict = true` with `param(..)` on a
  declaration stays rejected (a `#[fip_trait]` certificate carries no parameter
  bounds), with that message.

**Soundness.** Assume-guarantee, both sides in analysed code: every implementation in
an analysed crate is checked with `g` costing `K`; every call through the contract in
an analysed body passes an argument checked against `K` (an argument not known there
is `⊤` at the call site, as for any `param`). An implementation in a crate without
`fip::export` is `⊤` as before; calls from unanalysed crates are not checked (as for
`requires`).

## Resolved 2026-11-03: element paths and access-path preconditions (top plan T13.1, T13.2)

**Before.** Access paths of the value analysis were `(*p).f1.f2…` (fields only) below

lazily initialised `thread_local!`.

like direct FFI marks (by symbol and ABI); a term the use site cannot resolve is an

## Resolved 2026-11-03: the analysis cache follows the std summaries' content

**Before.** `cargo fip-prelint` keyed cargo's cache (replayed diagnostics of a crate
that compiled) on the driver binary (`FIP_PRELINT_DRIVER_ID`: size and modification
