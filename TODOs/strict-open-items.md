# TODO: open items of `#[fip(strict = true)]` and `FipFn`

**Status:** items 1–4, 8, 9 DONE; 5 and 10 INHERENT for the attribute macro but CAUGHT by `fip-prelint` (MIR, 2026-11-01); 7 INHERENT, and **not** checked by `fip-prelint` either (measured); 6 MITIGATED (reasons below).
**Recorded:** 2026-11-01. **Updated:** 2026-10-31.
Design and limits: `docs/decisions/2026-11-01-strict-core-table.md`.

| # | item | status | resolution |
|---|---|---|---|
| 1 | Verus specifications for `FipFn` | DONE | Probed first (Verus 0.2026.10.18.7d82994): an `unsafe trait` with an associated const, a trait with `spec fn pre/post` and `call` requiring/ensuring them, a generic closure wrapper whose `pre`/`post` are the closure's `requires`/`ensures`, and HRTB bounds `for<'a> FipFn<(&'a T,)>` all verify. `fip-strict` now declares `FipBound`, `FipFn`, `Certified` twice: plainly, and in `verus! { }` under `cfg(verus_keep_ghost)`; `tests/verus_drift.rs` checks that both declare the same exec items (a mutant with a changed `call` signature fails it, `just verify-negative`). `fip_fn!` now yields `fip_strict::Certified<{bound}, _>` (no item declared: measured, Verus rejects item statements in verified bodies — "internal item statements" unsupported — while the const-generic form verifies inside a verified caller, `verify/compose_strict.rs`). `just verify-strict` verifies `fip-strict` (7 verified, `--no-cheating`) and exports its Verus metadata. Limit: `fip_fn!` supports closures of arity 0–4 (`fip_strict::MAX_ARITY`). |
| 2 | strict variants of `fip-core`'s higher-order functions | DONE | `fip_core::strict::{compact, dedup_by, compact_map, map_in_place, update}` take `FipFn` callables, are `#[fip(strict = true, param(.. = 0))]` in plain builds and Verus-verified with `--no-cheating` (fip-core 36 verified). Specs written first as `compact_post`/`compact_fip_post`, `dedup_fip_post`, `compact_map_fip_post` (`spec.rs`) and pre-verified: `compact_post` accepts `[1,2,3,4] → [2,4 | 3,1]` and rejects an unmoved and a reordered answer; for any `FipFn` whose `post` is the example relation, the `*_fip_post` forms accept/reject exactly the cases of the already pre-verified relational specs. 7 new Verus mutants (5 implementation, 1 spec relation, 1 `Certified::pre`) are rejected. `fip-core` now depends on `fip-macros` (proc-macro, host only) and imports `fip-strict`'s Verus build under `verus`. Behaviour vs. the `Fn` versions and zero allocations: `fip-core/tests/strict_behaviour.rs`. |
| 3 | certificates for methods of generic types | DONE | `#[fip_macros::fip_impl]` on the `impl` block emits module-level certificates `__fip_strict_<Type>__<m>` before the block; strict callers use them for `Type::m(..)`, `a::Type::m(..)`, `<Type<..>>::m(..)` and `Self::m(..)`. The old associated-constant scheme is gone: a strict method with a `self` receiver outside `#[fip_impl]` is a compile error; `Self::m` outside it too. Rejected as ambiguous: bounds on impl parameters / `where` on the impl (another impl could define the same name), self types other than `Name<exactly the impl params>`. Tests: `fip-macros/tests/strict_impl.rs`, `strict_accept.rs`; misuse: 9 `compile_fail` examples. |
| 4 | trait-impl methods | DONE | Same attribute: `impl Tr for Type` gives `__fip_strict_<Type>__<Tr>__<m>`, reached only by `<Type as Tr>::m(..)` / `<Self as Tr>::m(..)` (`Type::m` would pick an inherent method of that name first, and is rejected unless that inherent method is strict). Generic traits (`impl Tr<u8> for S`, `<S as Tr<u8>>::m`) are rejected. Remaining: trait default methods (declared in the trait, not an impl) have no certificate. |
| 5 | implicit calls | INHERENT for the macro; **caught by `fip-prelint`** | **Update 2026-11-01:** `fip-prelint` (MIR) reports both `strict_gaps` cases as errors: the `Box` argument's drop (`may free`) and the allocating `Add` (`may allocate 1`, plus the free inside it). `tools/fip-prelint/tests/selfcheck.expected` pins these diagnostics, so `strict_gaps.rs` is now the test fixing this behaviour for the driver (and still the measurement of the macro's gap). Original note:  A token-level macro sees no types, so it cannot find `Drop` glue, overloaded operators, `Deref`, `Index` on user types. Measured (`fip-macros/tests/strict_gaps.rs`): a strict function dropping its `Box` argument is accepted and frees once; one using `+` on a user type whose `Add` allocates is accepted and allocates once. `fip_testkit::assert_fip!` fails on both (it counts frees and allocations), so the run-time check covers what the tests execute. Static closure would need type information (a rustc driver / lint plugin), which is not dependency-free. |
| 6 | panic paths | MITIGATED | New opt-in `#[fip(strict = true, panic_macros = false)]` rejects `assert!`, `assert_eq!`, `assert_ne!`, `debug_assert*!`, `unreachable!`, `panic!` (`compile_fail` example). Measured: a panicking strict function allocates on the panic path under `std` (`strict_gaps.rs::panic_path_allocates`). Not covered: panics from indexing, arithmetic overflow, division and callees, which the macro cannot see; `panic = "abort"` or a `no_std` panic handler that does not allocate is the user's choice. |
| 7 | generic checks under `cargo check` | INHERENT on stable Rust; **not checked by `fip-prelint`** (measured) | **Update 2026-11-01, measured** with the item's own example (`f` with `param(g = 0)` called with `fip_fn!(\|x: u8\| Box::new(x))`) under `cargo fip-prelint`: from a non-root caller nothing is reported; from a `#[fip]` root the closure's allocation counts against the **root's own** budget (error: may allocate 1, at most 0), but from a `#[fip(1)]` root the violation of `f`'s declared `param(g = 0)` is **not** reported. So the driver analyses generic instances under `cargo check` (fixture `generics`), but it does not check call-site arguments against a callee's declared parameter bounds. That check exists elsewhere: the post-monomorphisation assertion of a full build, and the token-level `fip_testkit::summaries`, which checks every call of a `param(g = K)` function (`ArgumentExceedsDeclared`, test `arguments_are_checked_against_declared_bounds`); the driver can port that rule. Reproducer: `TODOs/fip-prelint.md`, "Declared parameter bounds at call sites". Original note:  Measured with rustc 1.99.1: the "argument exceeding the declared parameter bound" example is accepted by `--emit=metadata` (what `cargo check` runs) and rejected by a full build. `ALLOCS <= K` for a generic `F` needs `generic_const_exprs` (unstable) to become a trait bound; on stable it is a post-monomorphisation constant. `Certified` now carries the bound in its type, so a future stable const-generic comparison could move the check to type checking. |
| 8 | `core` table is audited, not proved | DONE (audit), limitation stays | `fip-macros/tests/strict_toolchain.rs` fails when the compiling rustc (recorded by `fip-macros/build.rs`) is not in `fip_lint_rules::CORE_TABLE_AUDITED_AT` (measured: fails on 1.96.0). 1.97.1 `core` sources read for all 11 table entries; identical to 1.99.1 except `<[T]>::swap` (1.97.1: `ptr::swap` on two indexed places; 1.99.1: bounds checks + `swap_unchecked`; both drop nothing and call no user code); "1.97.1" added. Line references in the decision record. Still audit, not proof: `vstd` specifies 7 of the 11 entries (`mem::swap`, `size_of`, `align_of`, `<[T]>::len`, `is_empty`, `split_at`, `split_at_mut`), functionally and as trusted `assume_specification`s; none states "no deallocation". |
| 9 | certificate re-export without `unsafe` | DONE | `Cert` carries its function's name (`Cert::assume("f", n)`, `fip_strict::certs` entries name theirs); strict callers read bounds through `Cert::allocs_for("f")`, which fails constant evaluation on a mismatch, so `use a::__fip_strict_g as __fip_strict_f;` no longer compiles where `f` is called (`compile_fail` example). Remains possible: importing the certificate of a same-named function from another module (`use a::__fip_strict_f;` next to a local `fn f`); `fip_testkit::certs::hand_written` still reports every `__fip_strict_` identifier in source. |
| 10 | `use` aliases of table functions | INHERENT for the macro (by design); **resolved by `fip-prelint`** | **Update 2026-11-01:** `fip-prelint` sees the resolved callee of an alias (fixture `cross_crate`, `via_alias`). Original note:  Rejected on purpose: the macro sees only the alias name, and resolving `use` needs name resolution. Call table functions by their `core::`/`std::` path. Not a bug. |
